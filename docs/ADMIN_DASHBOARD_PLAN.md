# 研究管理后台方案与待办

更新日期：2026-11-19（Asia/Shanghai）

## 目标

为约 100 名及以上参与者提供研究团队使用的运行监测后台，减少逐个登录检查。后台用于查看进度、识别需要人工联系的参与者、了解单次练习历时，并按授权只读查看训练记录。首期不通过平台向参与者发送提醒，不改变现有训练流程、数据采集字段或研究数据内容。

## 已确认的产品口径

- 参与者的入组日期定义为首次完成模块 `1-1` 的时间；首次输入编号并登录不算正式入组。
- 完成整个六周训练以模块 `6-7` 的完成记录为准，不根据登录日期或推算进度判断是否结业。
- 参与者可能暂停或退出，后台需要能区分进行中、暂停、已退出和已完成；暂停期间不累计未完成天数。
- 首版暂停/退出是研究管理与提醒状态，不封禁参与者登录，不改变课程解锁规则；若要阻止退出者继续训练，需要另行确认并实现参与者侧规则。
- 管理员可以按需查看参与者训练内容，但只读，不把管理员身份切换成参与者身份，也不允许从查看页面提交、完成或重置模块。
- 现阶段可由同事共用一个工作人员后台账号，暂不要求新增多个账号；此取舍意味着审计记录只能识别为同一个后台账号，无法确定是哪位同事操作。后续若需要个人责任追踪，应改为每人独立账号。

## 当前身份与权限边界

代码库公开配置中，Cloudflare `wrangler.toml` 与内地部署环境模板均将 `C_TEST` 配为 tester，`ADMIN_PARTICIPANT_CODES` 为空。生产服务器的实际环境变量不在仓库中，不能仅凭代码库断定线上目前配置了几个管理员编号。

`C_TEST` 是参与者侧的测试身份，不是工作人员后台账号。tester/admin 参与者角色拥有全模块访问能力，且可重置已完成模块；继续用它承载后台登录会混淆测试数据与工作人员行为，并扩大误操作风险。因此后台应有独立工作人员认证，即使当前只有一个可共用的工作人员账号，也不要复用 `C_TEST` 或参与者编号+姓名登录流程。

工作人员会话应由服务端签发，使用 `HttpOnly`、`Secure`、适当 `SameSite` Cookie，设置过期、退出、登录失败限流和 CSRF 防护。后台凭证、口令或导出 Bearer Token 不得写入前端代码或浏览器存储。首期只开放只读查询和有审计记录的导出；参与者重置、编辑数据等写操作不属于后台能力。

## 信息架构

### 总览

- 首次完成 `1-1` 的正式参与者数。
- 完成 `6-7` 的人数和结业率。
- 今日应完成且已完成的人数/比例。
- 进行中、暂停、退出、已完成数量。
- 达到连续两天未完成阈值的人数。
- 数据更新时间和所选统计日期（统一以 `Asia/Shanghai` 展示）。

指标可下钻：点击总览指标后进入被试列表，并自动应用对应筛选，而非打开一个没有上下文的独立图表页。

### 参与者列表

每位参与者一行，支持编号/姓名搜索、状态筛选、提醒筛选、最近完成时间和进度排序、服务端分页。建议列：研究编号、显示姓名、状态、首次完成 `1-1` 日期、完成天数/42、最近完成模块与日期、最近一次训练历时、连续未完成天数、提醒状态。

### 参与者详情

桌面使用右侧详情抽屉，保留列表筛选和滚动位置；手机使用独立详情页。先显示参与状态、入组时间、当前进度、未完成提醒依据和逐日训练时间线。单次训练至少显示模块、状态、服务器记录的开始/完成时间、历时以及可用时的练习计时。

详情中提供“查看训练内容（只读）”入口，按参与者和模块读取已保存的快照、消息、输入和 AI 调用记录。页面明确标注只读，不创建参与者会话、不调用 AI、不写入事件、不提供完成或重置按钮。查看敏感原文与导出都写审计记录；首版可将“总览/列表”和“敏感内容/导出”作为不同能力开关，即使暂时由同一工作人员账号持有。

## 统计口径

- 入组人数：至少有一条 `1-1` `completed` 记录，且不是测试数据。
- 结业人数：有 `6-7` `completed` 记录。结业率按“结业人数 / 入组人数”展示，同时单列暂停和退出人数，不静默把他们从分母移除；必要时再提供“仍在进行者结业率”作为次要指标。
- 每日完成率：在今日上海自然日开始前已入组、查询时状态为进行中、且今日开始前尚未结业的参与者为分母；其中今日完成任一模块记为已完成。今日首次完成 1-1 不计入分子或分母；今日完成 6-7 仍计入二者，次日才退出应训练人群。此为实时快照，不是历史逐日考勤报表；今日暂停/退出后即从实时应训练人群移除。
- 入组日对应 Day 1；后续应训日期按参与者入组日逐日计算。由于当前训练模块按“完成前一天后，次日上海时间解锁下一天”解锁，训练日与页面解锁依赖完成情况，提醒只表示“应训日未完成”，不改变解锁规则。
- 两日提醒：从最近一次完成训练的次日起，累计已完整过去的上海自然日，扣除暂停日期，达到两日提醒。今日尚未结束，不算缺勤；补做任何模块后重新计数，不按模块序号推算日历日期。暂停采用半开日期区间 [暂停日期, 恢复日期)，同日暂停恢复不额外扣日；暂停/退出/已结业者不提醒。不限制最多 42 个日历日，因为补做可能延长实验日程。
- 参与者可以暂停/退出，因此需新增状态记录能力及状态生效日期；暂停期间冻结应训日序列，恢复时继续原有序列，不把暂停日期计作缺席。每次状态变更记录时间和操作者。
- 时长优先并列展示服务器记录的 `elapsed_duration_seconds`（开始到完成的墙钟历时）与客户端 `practice_duration_seconds`（练习计时）。历时可能包含后台、停留或中断；客户端计时也可能受设备与浏览器影响。两者仅作为研究辅助线索，不自动评判认真程度或训练质量。
- 所有汇总排除 `metadata.testData=true` 的测试记录。不得仅按 `C_TEST` 字符串排除，以免测试标记与身份名单不一致。

## 技术与部署建议

- 后台前端复用本仓库 `src/` 和现有 EdgeOne Pages 发布，不需重写前端、不需新增域名或单独购买网页空间；可使用同域 `/admin` 路由。页面 URL 不是安全边界，所有数据接口都必须在后端认证和授权。
- EdgeOne Mainland 构建的后台固定连接 `https://api.resilience-training.cloud`，数据只来自腾讯云 PostgreSQL；Cloudflare 构建若后续需要后台，则使用独立 Worker/D1 认证与数据，不能混合两边数据。
- 新增专用管理 API：汇总、参与者分页/筛选、单人进度时间线、只读模块记录、暂停/恢复/退出状态、导出及审计。不得让浏览器调用现有全量导出接口并持有 `ADMIN_EXPORT_TOKEN`。
- 聚合在服务端完成；100+ 人的规模很小，但仍采用服务端分页、限定过滤范围和响应字段，避免把整库原文下载到浏览器。
- 数据库新增工作人员认证配置/会话、参与状态历史和管理审计表之前，需确定首期共用账号的凭证初始化与重置方式。不要把明文口令放进仓库或与参与者账号共用。
- 不新增第三方分析、邮件/短信提醒、数据同步或额外数据库服务。现有腾讯云/PostgreSQL 预计足以支持该规模，仍需通过索引与查询计划验证。

## Roadmap：M6 研究管理后台

### 当前实现状态（2026-11-19）

- M6-0 已落实首版统计口径：入组=完成 1-1；结业=完成 6-7；连续两日提醒按北京时间完整应训日；暂停区间从日程中扣除。新增 8 项回归覆盖上海午夜、补做重计、入组当天、结业当天、跨暂停区间、超过 42 日及凭证轮换。
- M6-1 已实现工作人员独立登录、scrypt 密码哈希、限流、8 小时 HttpOnly/SameSite Strict Cookie、数据库会话与退出撤销、来源校验、认证查询和审计表。凭证尚未配置到生产环境。
- M6-1 已有 Mainland 只读总览、参与者列表/分页/搜索/状态和提醒筛选、排序、训练进度详情 API。Cloudflare Worker/D1 没有后台 API，Cloudflare 构建中的 `/admin/` 会提示仅支持 Mainland。
- M6-2 已实现 `/admin/` 登录页、五项总览指标、点击指标下钻、参与者列表、桌面详情抽屉/手机全屏详情、暂停/恢复/退出控件。首版详情仅展示状态和时长，不展示训练原文。
- Postgres/PGlite 管理接口集成测试、100+ 人分页样本、Edge 桌面/手机真实浏览器回归、15 项媒体/UI 测试、8 项共享契约测试、Mainland/Cloudflare 构建及 Worker 类型检查通过。腾讯云 0002 数据库迁移、线上凭证设置和线上后台验证尚未执行。
- 发布步骤与回退方式见 [M6_ADMIN_DASHBOARD_DEPLOYMENT.md](M6_ADMIN_DASHBOARD_DEPLOYMENT.md)。M6 先推送独立候选分支 `release/m6-admin-dashboard`，不更新当前 EdgeOne 生产分支；腾讯云后端通过验收后再切换前端构建分支。
